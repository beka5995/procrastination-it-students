# Questionnaire Draft

This draft operationalizes the variables defined in SS5. It is intended as a working instrument, not as a finalized validated scale.

## Participant and Study Context

1. Study year: 1 / 2 / 3 / 4
2. Programming experience: number of semesters
3. Typical study format: Individual / Group / Mixed
4. Device setup: One screen / Multiple screens
5. Sleep last night: hours
6. Sleep quality: 1 (very poor) to 5 (very good)
7. Academic motivation for the current task/course: 1 (very low) to 5 (very high)
8. Task difficulty: 1 (very easy) to 5 (very difficult)
9. Task importance: 1 (very low) to 5 (very high)
10. Days until the nearest important deadline
11. Approximate study hours per week
12. Number of parallel deadlines

## RQ1 — Digital Distraction Frequency

During a typical academic / coding session, how often do you:

- Check messaging applications?
- React to notifications?
- Switch between browser tabs?
- Switch between an IDE and a browser?
- Consume background media?
- Open unrelated social media?

Use a 1–5 scale:
1 = Never, 2 = Rarely, 3 = Sometimes, 4 = Often, 5 = Very often.

## RQ2 — Context Switching and Cognitive Load

- Approximate number of context switches per hour.
- Frequency of background multitasking: 1–5.
- Mental demand during the task: 1–5.
- Effort required to continue the task: 1–5.
- Difficulty maintaining focus: 1–5.
- Difficulty regaining focus after an interruption: 1–5.
- Mental fatigue after the task: 1–5.

The four cognitive-load items are averaged into the **Cognitive Load Index (CLI)**.

## RQ3 — Academic Procrastination

Rate each statement from 1 (strongly disagree / almost never) to 5 (strongly agree / very often):

- I delay starting or continuing an academic task.
- I avoid the main task when it becomes mentally demanding.
- I replace the main task with easier or less important activity.
- I switch from academic work to unrelated digital content.

The four items are averaged into the **Procrastination Index (PI)**.

## Important Note

This questionnaire should be pilot-tested before final data collection. The project checks internal consistency using Cronbach's alpha.
